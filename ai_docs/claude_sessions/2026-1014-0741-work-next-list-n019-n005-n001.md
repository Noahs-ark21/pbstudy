## N-005: premise corrected, left Open with a question (`ea638fd`)

The item proposed removing "a file whose id no longer exists anywhere". That
cannot converge for a live tag:

- `ApplyTag` keeps both machines' local ids by design.
- Export rewrites any local row whose file is missing (`syncer.go`,
  `doExport`).
- So deleting the redundant file just makes the minting machine write it back.

The fix that would converge is **tag-id convergence** on a name merge:

1. Both machines adopt one deterministic id (say, the smaller UUID).
2. `note_tags` is re-pointed to it.
3. The losing id is tombstoned, so compaction clears its file.

That changes tag identity across machines, which `ApplyTag`'s comment argues
against. The question is written into the item: is that worth doing for one
small file per machine per shared tag, or should the item move to Non-goals?

### The defect: N-021, raised and fixed

The popup quoted **NKJV** on a KJV page. Reading `BLB.Tagger` after load
showed that the tagger replaces the object with its own defaults:

- `Translation: "NKJV"`
- `HyperLinks: "none"`. The field takes a string (`all`, `none` or `hover`);
  ours sent a boolean.
- `Style: "par"`
- `NoSearchClassNames: ""`, so `NoSearchClasses` was only
  `{noTag, doNotTag}`.

So the inline `BLB.Tagger = {...}` that `layout.go` placed *before* the
script tag was always discarded. Its comment claimed the opposite. Two
throwaway pages in the same tab, written with `document.write`, settled it:

| Page | Config placement | Popup version | `blb-no-tag` div tagged? |
| --- | --- | --- | --- |
| Control | the app's order (inline, before the tag) | NKJV | yes, so double-linking was possible in the reader and search |
| Fix | property assignments in a deferred script after the tag | KJV | no; the tagger reads `NoSearchClassNames` when it starts tagging, which is after its async YUI and loader fetches |

What changed:

- **`assets/js/blb-tagger.js`** (new) reads `data-translation` and
  `data-no-tag` from its own `<script>` tag (`document.currentScript`). It
  sets `Translation`, `HyperLinks = "all"`, `TargetNewWindow` and
  `NoSearchClassNames = "noTag doNotTag " + ours`. If BLB didn't load
  (offline), it does nothing.
- **`blb/blb.go`:** the inline config function was removed in favour of
  `TaggerConfigScript` (the path) and `TaggerTranslation()` (KJV or ASV,
  from a fixed set). The dropped keys `DarkTheme` and `Style: "default"`
  were never real tagger options; the defaults already render the dark popup.
- **`web/ui/layout.go`:** emits the tagger tag and then the config script,
  both deferred. Deferred scripts run in document order.
- **`web/ui/layout_test.go`:** `TestTaggerConfigFollowsTagger` checks that
  the config tag comes after the tagger, that no inline `BLB.Tagger =` is
  back, and that the data attributes are present.

Verified in the real app afterwards: `Translation` is "KJV", `HyperLinks`
is "all", `NoSearchClasses` includes `blb-no-tag`, nothing inside a
`blb-no-tag` element is tagged, and the hover popup reads "Romans 8:28 (KJV)".
